# AI-агент в моделере

[go-bpm modeler](/modeler/) встраивает MCP-сервер. Через него AI-агент — Claude Code, Cursor или другой с поддержкой
[Model Context Protocol](https://modelcontextprotocol.io) — работает со схемой вместе с вами: видит, что вы рисуете
прямо сейчас, включая несохранённые изменения и выделенные элементы, отвечает на вопросы, находит ошибки и
предлагает правки. Правка применяется, только если вы её подтвердите.

## Что понадобится

- go-bpm modeler со [страницы загрузок](/modeler/) — MCP-сервер есть в сборках начиная с канала dev от 31 октября 2026.
- Агент с поддержкой MCP по HTTP: [Claude Code](https://docs.anthropic.com/en/docs/claude-code),
  [Cursor](https://cursor.com) или другой.
- Рабочая папка, открытая в моделере, — обычно `process/` сервиса go-bpm.

Агент и моделер работают на одном компьютере: сервер принимает подключения только с него.

## Включить MCP-сервер

1. Запустите моделер и выберите рабочую папку («Папка» на панели инструментов).
2. Нажмите **«AI-агент»** справа на панели инструментов.
3. Включите **«MCP-сервер включён»**. На кнопке загорится зелёная точка, в окне появятся адрес сервера, команда
   подключения и токен.

Моделер запоминает выбор: при следующем запуске сервер включится сам. Выключить — тем же флажком.

Токен — пароль агента. Кнопка **«Новый токен»** выдаёт новый, старый сразу перестаёт работать: агента нужно
подключить заново.

## Подключить агента

### Claude Code

Скопируйте команду из окна «AI-агент» и выполните её в терминале:

```sh
claude mcp add --transport http go-bpm-modeler http://127.0.0.1:39190/mcp \
  --header "Authorization: Bearer <токен из окна>"
```

Без `--scope` сервер подключается к текущему проекту — каталогу, где вы запустили команду. Чтобы моделер был доступен
во всех проектах, добавьте `--scope user`.

Проверить: `claude mcp list` в терминале или `/mcp` внутри Claude Code — сервер `go-bpm-modeler` должен быть
`connected`.

### Cursor

Добавьте сервер в `~/.cursor/mcp.json` (для всех проектов) или `.cursor/mcp.json` в проекте:

```json
{
  "mcpServers": {
    "go-bpm-modeler": {
      "url": "http://127.0.0.1:39190/mcp",
      "headers": { "Authorization": "Bearer <токен из окна>" }
    }
  }
}
```

### Другие агенты

| Параметр | Значение |
|---|---|
| Транспорт | Streamable HTTP |
| Адрес | `http://127.0.0.1:39190/mcp` |
| Заголовок | `Authorization: Bearer <токен из окна>` |

Сервер отвечает на POST обычным JSON, без потока SSE: присылать агенту что-то по своей инициативе ему не нужно.

## Как работать вместе

Агент при подключении получает инструкцию: сначала прочитать справочник о том, что поддерживает go-bpm, потом
смотреть, что открыто в редакторе. Говорите с ним как с коллегой, который видит ваш экран.

**Консультация.** Откройте схему и спросите:

- «Что не так с процессом в открытой вкладке? Объясни ошибки линтера».
- Выделите задачу: «Что делает выделенная задача и какие поля нужны в модели данных?»
- «Объясни таблицу решений Offer: какое правило сработает для заказа на 12 000 у клиента gold?»

**Правка.** Попросите изменение — агент пришлёт схему целиком, моделер покажет вам диалог с описанием правки:

- «Добавь эскалацию: если заказ не согласовали за 3 дня, уведомить руководителя».
- «Переименуй элементы с id вида Activity_0abc в понятные: CheckOrder, NotifyClient».
- «Поставь default flow у шлюза „Крупный заказ?“».

**Новая схема.** «Нарисуй процесс возврата заказа в orders/refund.bpmn: заявка, проверка менеджером, возврат денег
через service task» — моделер спросит, создавать ли файл, и откроет его.

Выделение работает как указка: выделите элементы на схеме и спросите про «выделенное» — агент получит именно их.

## Подтверждение правок

Когда агент хочет изменить схему или создать файл, окно моделера выходит на передний план с вопросом: какой файл,
что меняется и зачем — своими словами агента.

- **«Да»** — правка появляется в редакторе. Вкладка отмечается несохранённой: на диск ничего не записано, сохраняете вы
  (Ctrl+S) — или закрываете вкладку без сохранения, если правка не понравилась.
- **«Нет»** — схема не меняется, агент получает отказ и обычно спрашивает, что сделать иначе.

Если агент прислал схему, которую нельзя разобрать, она не применяется — ваша схема остаётся как была, агент получает
ошибку и может исправиться.

После правки агент видит проблемы линтера: ошибки — то, что отвергнет генератор go-bpm. Хороший агент проверяет их
сам; если нет — попросите «проверь схему после правки».

## Инструменты агента

| Инструмент | Что делает | Ваше подтверждение |
|---|---|---|
| `get_modeling_guide` | справочник: какие элементы и свойства поддерживает go-bpm и в каком формате | нет |
| `list_files` | файлы `*.bpmn` и `*.dmn` рабочей папки | нет |
| `read_file` | сохранённый файл рабочей папки | нет |
| `list_open_diagrams` | вкладки редактора: какая активна, есть ли несохранённые изменения | нет |
| `get_diagram` | XML схемы во вкладке, включая несохранённые изменения | нет |
| `describe_diagram` | элементы, настройки go-bpm, переходы, таблицы DMN и проблемы линтера | нет |
| `get_selection` | элементы, которые вы выделили | нет |
| `update_diagram` | заменить схему во вкладке новой | да |
| `create_diagram` | создать файл в рабочей папке и открыть его | да |

У инструментов вкладок есть аргумент `path` — путь файла; без него — активная вкладка.

## Безопасность

- Сервер выключен, пока вы его не включите.
- Слушает только `127.0.0.1` — с других компьютеров к нему не подключиться.
- Без токена — отказ. Токен хранится в настройках моделера, доступных только вашему пользователю.
- Запросы со страниц в браузере отвергаются (проверка заголовков `Host` и `Origin`): сайт не сможет обратиться к
  моделеру через ваш браузер.
- Агент видит только рабочую папку: пути за её пределами отвергаются.
- Изменить схему или создать файл — только через ваше «Да». Записать на диск правку агента можете только вы.

## Ограничения

- Правка — это схема целиком: агент присылает весь XML, а не отдельный элемент. Отменить её через
  Ctrl+Z нельзя — схема загружается заново. Если правка не нужна, не сохраняйте вкладку.
- Агент видит открытые схемы, пока моделер запущен. Закрыли моделер — агенту доступны только инструменты, которые
  ему даёт сам клиент (например, чтение файлов в Claude Code).
- Схему, которую агент хочет изменить, лучше открыть: если файл не открыт, моделер откроет его сам перед правкой.

## Если не работает

| Что видно | Что сделать |
|---|---|
| В окне «AI-агент» — «порт 39190 занят» | Порт занят другой программой. Задайте другой в настройках моделера: `"mcpPort": 39191` в `settings.json` и перезапустите моделер — адрес в команде подключения изменится. |
| Агент: `401` | Токен устарел — нажимали «Новый токен». Подключите агента заново командой из окна. |
| Агент: не удалось подключиться | Моделер не запущен или сервер выключен — проверьте точку на кнопке «AI-агент». |
| Агент: «рабочая папка не выбрана» | Выберите папку кнопкой «Папка». |
| Агент: «не открыт в редакторе» | Откройте файл во вкладке или попросите агента прочитать сохранённый файл. |
| Агент: «редактор не ответил» | Окно моделера занято другим диалогом — закройте его и повторите запрос. |

Настройки моделера лежат в `settings.json`:

| Система | Путь |
|---|---|
| Linux | `~/.config/go-bpm-modeler/settings.json` |
| macOS | `~/Library/Application Support/go-bpm-modeler/settings.json` |
| Windows | `%AppData%\go-bpm-modeler\settings.json` |
